Step 1 of the architecture · path generator · test plan · Nov 19, 2026, updated with the research report

Which kind of diffusion should turn our driving model's features into paths?

Today the 0.8B model writes its path as text, one number at a time (85.6 on NAVSIM). The next step replaces that text with a small path generator: a separate network that reads what the model has already understood about the scene and produces the 8 path points directly, several candidate paths at once. There are four ways to build that generator. This page explains each one, what the published work says about it, and how we will test all four head to head, since no one has compared them on NAVSIM with the same model and data. We report each one's effect, even where the gain is small, so we understand the system. The evidence behind it is in the research report, Driving action head diffusion type (same folder).

Evidence tags: V = read in the paper's text, tables or code; R = abstract or snippet only; D = our own arithmetic. Scores are NAVSIM v1 navtest PDMS, each paper's own report, so numbers across papers are context, not a controlled comparison.

  • Discrete with continuous extras: Discrete-WAM, about 1B, 92.2 final, the top masked-style number; no supervised-only score reported, and it relies on long pretraining (V).
  • Continuous diffusion DiT (B): ReCogDrive 86.5 → 90.8 after RL; DiffAdapterVLA on a frozen 8B model 88.3 → 90.3 (V). About 5 steps; the noise-predicting form scores 1.9 at 1 step (V).

  • Anchored diffusion (D): DiffusionDrive 88.1 (87.9 at 1 step, 2 steps standard; camera + LiDAR, no language model, V); DiffusionDriveV2 91.2 with RL and a selector, of which RL alone gave about +2.1 (V/D).

What every option shares

All four generators plug into the same place. The driving model reads the camera image and the prompt once, exactly as today, but instead of writing text it hands over its internal features. Those features are computed once and stored, so every generator trains on identical inputs and the comparison is fair.

One finding shapes all four options: which of the model's layers the generator reads matters a lot. With a frozen 8B model, reading only the final layer scored 80.2, while reading several late layers scored 85.2–86.9 (DiffAdapterVLA, V). GR00T also found a middle layer better than the last. So we store a few layers, not just the last one, and test that choice once.

One network body for all four. Following the one published same-body comparison (DiscreteRTC), every option uses the same transformer: about 16 layers × 384 wide (~35M parameters, ReCogDrive's planner size), cross-attention to the stored layers, and the car's speed and recent path entering through AdaLN. Only the input and output layers change between options, so differences come from the kind of diffusion, not from the network.

The four options

They differ in one thing: how the generator gets from "no path yet" to a finished path. That also decides how continuous the output is, how many candidate paths come out, and how reinforcement learning (RL) can train it later.

A · Masked diffusion over path tokens

test first (your choice)discrete

How it works. Each path point's x and y is rounded to a grid (for example every 10 cm), so a path becomes 16 "tokens", like 16 words. Training hides a random share of them and asks the generator to fill them back in. To make a path, it starts with all 16 blank and fills in the ones it is most sure of over a few rounds. This is the same idea as the language-diffusion model we forked (MVLAD-AD), but as a small separate network instead of the whole language model.

How continuous
Discrete only in what it samples: 0.1 m bins (about 4 cm average rounding, D). Everything else is metric: bin embeddings that know each bin's distance in metres, soft labels that also credit neighbouring bins, an extra position-error loss, and a readout averaged within the chosen bin's neighbourhood. These are added one at a time (the ladder below).
Steps
4 rounds, most-confident tokens first, end point first; we also run 1, 2 and 8. Published: ReflectDrive peaks at 5; DriveFine 90.5 at 4 (V).
K paths
Sample 3–6 end points about 1 m apart, then fill in each path; all in one batch over the same stored features.
Published
Masked-diffusion planners score 84.8–86.7 before RL and 90–91 after (WAM-Diff 86.6 → 91.0, DriveFine 86.7 → 90.7, V). Filling the far end first beats near-to-far: 91.0 vs 88.9 (WAM-Diff, V). In robotics, with the same backbone, masked diffusion matched continuous diffusion: 95.1 vs 94.9 on LIBERO (Discrete Diffusion VLA, V).
RL later
Possible but less standard; with only 16 tokens our small generator can compute the exact likelihood of its fill-in order, which removes the usual difficulty.
Unknown
No driving paper uses a separate small masked-diffusion head on a normal model; every one runs it through the full language model. Ours would be the first.

B · Continuous diffusion (DiT)

continuousexploration arm

How it works. The path stays as real numbers. Training adds random noise to true paths and teaches a transformer (a DiT, conditioned on speed and step through AdaLN, reading the features through cross-attention) to undo it. To make a path, it starts from pure noise and removes noise over several steps. This is ReCogDrive's planner, the published recipe closest to ours.

How continuous
Fully continuous, no rounding.
Steps
Depends on what it predicts. Predicting the noise collapses at few steps: 1.9 at 1 step, 82.6 at 2, 87.0 at 5 (DiffAdapterVLA, V). Predicting the clean path directly holds up better, so that is what we do; the research says this plain form from pure noise is weak at few steps and gives near-identical paths (11% diversity, V), so we run it to measure that on our model, not as the main contender.
K paths
Start from K different noise draws, in one batch.
Published
ReCogDrive on the same model: text 84.1, MLP head 75.5, query decoder 85.0, plain diffusion 85.4, refined DiT 86.5, then 90.8 after RL (V). Its planner is ~35M parameters, 5 steps. Caution: on its 8B model text already scored 86.4, so the head added only +0.1 (README, V). The gain shrinks when the text model is already strong, as ours is.
RL later
Well established (ReCogDrive's DiffGRPO): each denoising step has an exact probability.

C · Flow matching

continuousexploration arm

How it works. A close cousin of B with the same network. Instead of learning to remove noise, it learns a direction to move each point, along a straight line from the random start to the true path. Straight lines can be followed in very few steps. This is the action-expert style used by π0 and GR00T.

How continuous
Fully continuous.
Steps
Often 1–5. GoalFlow: 88.9 at 1 step, 90.3 at 5 (V). The random start must be narrow: noise of 0.1 gave 90.3, 0.2 gave 49.0 (GoalFlow, V).
K paths
K different starts, in one batch.
Published
DriveVLA-W0's flow expert: 87.2 at 10 steps, but a simple regression head on the same model scored 88.4 (V). Flow-GRPO RL on a flow head: 90.8 → 92.3 (DriveWLA, V).
RL later
Works (Flow-GRPO, ReinFlow), with care at 1 step.
Our settings
A narrow start (noise about 0.1), 1, 2 and 5 steps. Small to test: same network, different training target.

D · Anchored diffusion (coarse choice + continuous refinement)

main comparison for Ahybrid

How it works. Collect about 20 typical paths from the training data (gentle left, straight, hard right, stopping, and so on). The generator scores which of these "anchors" fits the scene, then nudges each one onto the exact path in 1–2 continuous steps. It is half discrete (pick a type of path) and half continuous (refine it).

How continuous
Coarse choice, then fully continuous refinement.
Steps
1–2: 87.9 at 1 step, 88.1 at 2, against 84.6 for plain 20-step diffusion (DiffusionDrive, V).
K paths
Built in, one per anchor, and genuinely different: plan diversity rose from 11% to about 70% over plain diffusion (V). Quality levels off around K = 20 (84.9 / 88.1 / 88.2 at K = 10 / 20 / 40, V).
Published
DiffusionDrive 88.1 (no language model); with RL and a selector 91.2, of which RL alone gave about +2.1 (DiffusionDriveV2, V/D). RL lowered diversity from 42.3 to 30.3 (V), something to watch for the selector.
RL later
Works, but needs grouping by anchor, or RL collapses onto "go straight" (DiffusionDriveV2, V).
Our settings
About 20 anchors from the training paths, predicting the clean path, 2 steps. The research recommends this, not plain B, as the continuous head to compare against A: it is the only continuous design with NAVSIM evidence at few steps and with many different paths.

How continuous should it be?

"Continuous" is a scale, not a yes or no. Our text output already sits on it: the model writes each number with one decimal, so today it is effectively a 0.1 m grid.

Rounding figures: average error of a uniform grid is about 0.41 × the bin size (D). The one NAVSIM sweep (MD-Drive, inside a language model): 0.5 m bins 78.2, 0.25 m 81.4, 0.1 m 80.8 (V). Finer bins stopped helping there, but in a language model every extra bin is an extra word in its vocabulary; a separate generator can afford 1,000–2,000 classes (D). Below 0.1 m, rounding is no longer where the points are lost.

The "how continuous" ladder inside option A. One trained network, one change at a time, each scored on NAVSIM, so we see what each step of continuity is worth. No driving paper has isolated these, so every rung is new data:

  1. Hard labels on 0.1 m bins, bin embeddings that know distances (worth +2.3 in WAM-Flow, V).
  2. + soft labels that also credit the neighbouring bins.
  3. + an extra loss on position error, and a readout averaged around the chosen bin.
  4. + a small continuous offset per token (kept deterministic, so RL still works on the tokens).
  5. Side arms: 0.25 m and 0.05 m bins.

The test plan

  1. Store the features once. Run our best model (H1) over the training scenes (v1-hard, 236k), the 1,000 dev scenes and all 12,146 test scenes, and save a few of its layers. One job on the lab 4090; about 180 GB per stored layer for the training set (D), against 1.6 TB free, so a handful of layers fits.
  2. Build the shared network once, and settle which layers to read. Head A reading the last layer only vs several layers; the better choice is then fixed for every option.
  3. Option A and its ladder (the five rungs above), at 1, 2, 4 and 8 rounds.
  4. Option D, the main continuous comparison: about 20 anchors, 2 steps.
  5. Options B and C, the exploration arms on the same network: 1, 2, 5 and 10 steps for B; 1, 2 and 5 for C.
  6. A short, matched RL stage for A and D (and B, C if cheap): same group size, same number of updates, same scorer budget. This needs NAVSIM's score cache for the training scenes, built on Anvil's CPUs.
  7. Pick the head, then move on to the selector and full RL (steps 2–3 of the overall plan).

How we decide

We score every option twice: after supervised training, and again after the short matched RL stage. The research expects the options to land within about a point of each other after supervised training alone, so the deciding numbers are the ones after RL: the single-path score, together with the best-of-6 score (the room a selector will have). We keep A if it matches D within run-to-run noise and holds an equal or better best-of-6 at 4 rounds or fewer; we switch to D if D wins after RL by more than noise. Gaps under about half a point to a point in a single run count as ties. Every option's numbers are reported either way. Everything uses the same stored features, the same 236k training scenes and the same training budget, so the result is a clean comparison nobody has published for NAVSIM.

Two honest cautions. First, our text model is already strong (85.6), and ReCogDrive saw the head's gain shrink from +2.4 to +0.1 as its text model improved, so the first gain may be small; the larger gains in every paper come from RL and the selector that this step makes possible. Second, published work warns that over-fitting the supervised model leaves less room for RL (an over-fitted model gained only +1.5 from RL against +8.6 for a less-fitted one, MD-Drive, V), so we keep the checkpoint with the best best-of-K score, not the lowest training error.

What to expect. From 85.6, the published pattern adds a small supervised gain from the head (+0.1 to +2.4), then +2 to +4.4 from RL and about +1 from a selector: roughly 89–91 for one path after RL, and 3–4.5 points more for the best of 6. That is an extrapolation from 1.5–8B models, not a measurement; ReflectDrive-2 (0.7B, 91.0 after RL) shows the size class can get there.
